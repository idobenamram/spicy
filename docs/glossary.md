# Glossary

This glossary gives one approved name for each item in this project, with a short definition. Docs, code comments and agent replies use these names and link here instead of defining a term again.

A doc name such as `model.md` means a file in `docs/ecad/`. A label after it, such as E16 or §4, names a decision or a section of that doc. "Do not call it" lists other names that docs or past replies used for the same item.

<a name="language"></a>
## The language

- **block** (`spicy_model::design::Block`): the interface of a reusable piece of circuit: a name and its ports, for example `pub block CeAmp { vcc: Power<In>, … }`. You can place a block many times, and it has at most one circuit. In the code, one `Block` holds the header and the circuit. Defined in `language.md` §2–2.1.
- **circuit** (the item): the implementation of a block: its nets and its parts, for example `circuit CeAmp { net base … }`. Defined in `language.md` §2, §4.1. Not the same as `spicy_circuit::Circuit`, the input of the simulator.
- **const** (`spicy_model::design::Const`): a fixed value for the whole project, for example `const confidence: Confidence = sigma(3)`. Defined in `language.md` §2, §8.1.
- **contract** (`spicy_model::design::Contract`): the promises of a block: its default setup, its measures, its specs and, later, its `rated` limits. The header, the setups and the contract of a block are together the text form of its I/O (input/output) page in the editor. Defined in `language.md` §8.1.
- **default setup**: the setup that a contract names with `setup = Operating`. Specs run in it unless they name another setup, and the other setups of the block stay inside it. Defined in `language.md` §8.2 ("The default setup"). Do not call it: "accepted setup", "default bench" (the v0.1 name).
- **env** (`spicy_model::design::Env`): a range of the environment for the whole project, which the engine searches, for example `env ambient: Temperature in -10°C..=60°C`. A setup reads it with `temp: ambient`, and it becomes one range knob. Defined in `language.md` §2, §5.4. Do not call the knob `temp` (the engine docs do).
- **limit** (planned `Limit` in `spicy_model`): the part of a spec that says which values pass: `within <range>`, `<= <bound>` or `>= <bound>`. The bound is the number or the range in it. Defined in `language.md` §8.3, `contracts_plan.md` §0.2. Do not call it: "requirement", `in` (the v0.1 syntax).
- **measure** (planned `MExpr` in `spicy_model`): a value that the engine computes from simulations. A contract declares it with `let`, for example `let h = ac(output.v / input.v)`. It reads probes such as `output.v` through an analysis such as `dc` or `ac`. Defined in `language.md` §8.4, `model.md` E24.
- **net** (`spicy_model::design::Net`): a named connection between pins. You declare it with `net base`, and the ports of a block are nets inside its circuit. Flatten merges joined nets into one `FlatNet` and keeps the other names as aliases. Defined in `language.md` §4.1, `model.md` E15. The simulator calls a net a node.
- **placement**: a `let` in a circuit that places a block, for example `let left = CeAmp { vcc: v12, … }`. A `let` that places a part (`Resistor { … }`) is a part instance, and flatten makes each part instance a device (`FlatDevice`). Defined in `model.md` E6. Do not call a placement an "instance": the code type `spicy_model::design::Instance` covers both.
- **port** (`spicy_model::design::Port`): a named connection point on the boundary of a block. The header lists it as `name: Type`, for example `vcc: Power<In>`. The type (`spicy_model::prelude::SignalType`) says what the port carries and in which direction. Defined in `language.md` §3.1–3.2.
- **prelude** (`spicy_model::prelude`): the built-in part kinds and signal types: `Resistor`, `Capacitor`, `Electrolytic`, `Npn`, `Pnp`, `Power`, `Ground` and `Analog`. Resolve looks up a name in the prelude last. Defined in `model.md` E5, E8, `ARCHITECTURE.md#shortcuts`.
- **`pub spec`** (published spec): a spec that a parent block may rely on. It may name only the ports of its own block. A spec that names an internal net, a part or a child block is an internal spec, and `pub` on it is an error. Defined in `language.md` §8.3 ("`pub spec` and internal specs"). Do not call it: "guarantee", "promise", "fact".
- **setup** (`spicy_model::design::Setup`): a test environment for one block: what drives each input, what loads each output, and the temperature. It gives each port a shape (`spicy_model::prelude::Shape`), for example `vcc: Supply { v: 12V ± 5% }`. Defined in `language.md` §8.2. Do not call it: "bench", "testbench", "test setup", "fixture".
- **spec** (specification): a named rule in a contract: one measure must meet one limit, for example `spec bias: dc(output.v) within 4.5V..=6.5V`. The engine gives a verdict for each spec side. Defined in `language.md` §8.3, `specs.md` §1. Do not call it: "requirement".
- **`Step`** (a setup shape): a jump of one level at one time, `Step { from, to, edge, at }`, for example a load current that jumps from 5 mA to 30 mA. It is not in the MVP (minimum viable product). Defined in `language.md` §8.2 ("Events and faults"). Not the same as the `step` field of `Sweep { from, to, step }` (the increment), or a plan step.

<a name="stages"></a>
## The design model and the compiler stages

- **AST** (abstract syntax tree, `spicy_lang::parser::ast`): the typed tree of what the text says, with a byte span on every node. The parser (`spicy_lang::parser::parse`) builds it and turns broken text into error nodes. Defined in `ast.md` §3, §7.2. Do not call the parser "the reader": that name belongs to the netlist reader.
- **CST** (concrete syntax tree): a syntax tree that keeps every character as a leaf, so that the leaves join back into the file. The project chose an AST plus the full token list instead. Defined in `ast.md` §7.2. Do not call it: "lossless tree", "rowan" (a library that builds one).
- **design** (`spicy_model::design::Design`): the output of resolve: each block once, as written, with names resolved and values typed. It has one copy of each definition, not one copy for each placement. Defined in `model.md` §0, E1. Do not call it: "the hierarchy", "the design model" (the crate `spicy_model`, which also holds the flat design).
- **diagnostic** (`spicy_errors::Diag<K>`): one error or warning that a stage reports, as data: its kind, its span, an optional related span and an optional fix. Each kind has a code, such as `E-unit`. Defined in `ARCHITECTURE.md#code-map`, `lexer.md` L10. Do not call it: "error" (it can be a warning). The CLI (command-line interface) type `Problem` is a different item.
- **elaboration** (`spicy_lang::elaborate::elaborate`): the stages resolve and flatten together. Elaboration turns the AST into a design, and then into one flat design for each root. Defined in `model.md` §0. Do not call it: "M1d" (the milestone), "the model stage".
- **flat design** (`spicy_model::flat::FlatDesign`): the output of flatten for one root: every device by its path, the nets merged, and every spread as a knob. `spicy_model::flat::Flat` reads it together with its design. Defined in `model.md` §0, E14–E17. Do not call it: "the flattened circuit", "the netlist".
- **flatten** (`spicy_model::flatten::flatten`): the stage that turns the design into flat designs. In eight passes, it expands every placement, merges and names the nets, and makes each spread a knob. Defined in `model.md` §0, §3.5–3.6.
- **interning**: storing each distinct string once, and referring to it by a small number. The parser borrows names from the source text and does not intern them. Defined in `ast.md` A3, `model.md` §4.
- **intra-doc link**: a link in a Rust doc comment to a code item, for example ``[`Scope::declare`]``. `cargo doc` warns when such a link breaks. Defined in `docs/writing_docs.md` ("Code comments").
- **lexer** (`spicy_lang::lexer`): the stage that cuts `.spl` text into tokens, in two passes. `scan` never fails, and `check` reports diagnostics and decodes quantities such as `4k7`. The token list (`Tokens`) also keeps whitespace and comments (trivia). Defined in `lexer.md` §1, `grammar.md` §2.1. Not the same as the lexer of the netlist reader.
- **lowering**: turning a higher form into the input of the simulator, `spicy_circuit::Lowered`: the circuit, its `Params`, its names, the analyses and the solver options. Milestone M1e lowers a flat design at one knob point. `spicy_netlist::reader::lower` lowers a netlist. Defined in `model.md` §0, `pipeline.md` §2. Do not call it: "export".
- **pass**: one walk over the data of a stage, numbered in the top function of the stage. The lexer has 2 passes, resolve has 3, and flatten has 8. A loop inside a pass is not a pass. Defined in `lexer.md` L1, `model.md` E4, and the module comments of `spicy_lang::resolve` and `spicy_model::flatten`.
- **path** (hierarchical path, `spicy_model::flat::HierPath`): the dotted name of an item in a flat design, from its root, for example `left.r1`. Knobs, probes and results use the path as the stable identity of an item. Defined in `model.md` E14, E21, §4. Do not call it: "hierarchy path", `flat::Path`.
- **resolve** (`spicy_lang::resolve::resolve`): the stage that turns the AST into the design. It finds what each name refers to, gives each value its unit, and checks that the text binds every pin exactly once. Defined in `model.md` §0, §3.2–3.4.
- **root**: a block that no other block places. Flatten makes one flat design for each root, and the flag `--top` selects one root. Defined in `model.md` E3.
- **span** (`spicy_span::Span`): the byte range of an item in the source file. The AST keeps a span on every node. The design keeps its spans in a side table, `spicy_model::design::DesignSourceMap`. Defined in `ast.md` A2, `model.md` E22.
- **stage**: one part of the pipeline from `.spl` text to simulation: the lexer, the parser, resolve, flatten, and then lowering. `/stage-review` reviews one stage at a time. Defined in `pipeline.md` §2, `.claude/commands/stage-review.md`. Do not call it: "step", "phase". Not the same as an engine stage, or an amplifier stage in electronics.

<a name="engine"></a>
## The engine and its results

- **3σ-point search**: the method that finds the 3σ (three-sigma) point of a spec side. From two starts, it draws a straight line from slopes, jumps to the point that the line predicts is worst, simulates that point, and repeats. Defined in `engine.md` §5.5, `engine_plan.md` §2.6. Do not call it: "σ search", "worst-case-distance search".
- **affine form**: a straight-line estimate of a measure: a center value, one slope term for each knob, and an error term. The MVP does not use affine forms (decision D-F). Defined in `engine.md` §3.1, `walkthrough.md` §8, §10.2. Do not call it: "the line".
- **answer key**: the true results for a test circuit, found by brute force: every corner, 1,000 random interior points, and a coordinate search. The σ key checks `sigma(3)` independently. The test circuits form the adversarial suite. Defined in `engine_plan.md` §2.2, §8.1–8.2.
- **backend** (planned trait `spicy_engine::Backend`): a simulator that the engine drives through one interface. ngspice is the first backend, and our simulator becomes the second in milestone M4. Defined in `engine.md` §6, `engine_types.md` §4.
- **cone**: the knobs that can change one measure. A capacitor cannot change a DC (direct current) voltage, so the cone of `bias` has 7 of the 8 knobs. Defined in `engine_plan.md` ("Glossary"), §2.3.
- **confidence**: which knob points a spec must pass at: `worst_case`, `sigma(k)`, `yield(p)` or `nominal`. The default is `sigma(3)` for your specs and `worst_case` for automatic checks. The confidence of a spec gives its headline verdict. Defined in `engine.md` §3.6, `language.md` §8.3.
- **corner**: a knob point with every knob at one end of its range. The CE (common-emitter) amp has 8 knobs, so it has 2^8 = 256 corners. Defined in `engine_plan.md` ("Glossary"), `walkthrough.md` §5.2.
- **counterexample**: a knob point that breaks a spec side, printed as knob values that you can paste after `spicy sim --at`. A knob outside the cone prints as `any`. The flip table moves each knob of the counterexample to its other end, one knob at a time. Defined in `engine.md` §3.5, `engine_plan.md` §3.4.
- **engine** (planned crate `spicy_engine`): the code that turns a flat design and its contract into verdicts. It never reads syntax, and it never imports a simulator crate. Defined in `engine.md`, `ARCHITECTURE.md#ownership`. Do not call it: "the simulator".
- **engine check**: one full run of the engine on one root, through the five engine stages. It gives a verdict for every spec side. Defined in `engine_plan.md` §0, §2. Not the same as `spicy check`, which never simulates.
- **engine deck** (planned `spicy_backends::ngspice::EngineDeck`): the flat design as a netlist with one `.param` for each knob, plus a knob map and a probe map. ngspice loads it once and runs it again at each knob point. Defined in `engine_plan.md` §1.4, §5.1.
- **engine stage** (planned trait `spicy_engine::Stage`): one of the five parts of an engine check. In order: `Nominal` (one run), `Enumerate` (every corner), `Inside` (the guards), `Sigma` (the 3σ-point search) and `Band`. `Band` runs the decisive points again at tight tolerances. Defined in `engine_types.md` §5.1. Do not call it: "step" (`walkthrough.md` §5 and `engine.md` §5.1 number them step 0 to step 4).
- **guard**: a cheap test that looks for a worse value inside the knob box (every knob anywhere in its range), away from the corners. The guards are the tangent check, 8 audit points, and pooling. When a guard finds a worse value, an ascent (a local search) starts from that value. Defined in `engine_plan.md` §2.5. Do not call the tangent check "the interior check".
- **inner bound**: the worst value that a simulation actually reached. It can prove a FAIL. An outer bound is a proven limit that the true worst value cannot pass, so it can prove a PASS. The MVP has no outer bounds. Defined in `walkthrough.md` §4, `engine.md` §3.2.
- **knob** (`spicy_model::flat::Knob`): one independent value that can vary over a range, for example `r1.value` or `vcc.v`. A range knob is an operating condition that must hold at every value. A statistical knob is the manufacturing spread of a part. Defined in `engine.md` §2–2.1, `model.md` E16. Do not call it: "parameter", "variable".
- **knob point** (planned `spicy_engine::Point`): one value for every knob. The engine writes it as ε (epsilon) for each knob: −1 at the low end, 0 at nominal, +1 at the high end. Defined in `engine_plan.md` ("Glossary"), `engine_types.md` §2.1. Do not call it: "board" (`walkthrough.md`). Do not call ε a "noise symbol" or a "tolerance symbol".
- **read-back**: after every run, the engine reads each knob value back from the simulator. A difference stops the engine check with UNDECIDED (binding). Defined in `engine_plan.md` §4.4.
- **rev** (revision): a hash of the elaborated design, its knobs and contract, the engine settings and the backend identity. The engine stores each report under its `rev`, so a report for another `rev` is stale. Defined in `engine.md` §8, `engine_plan.md` §1.2.
- **run**: one simulation at one knob point. A round is one batch of runs that the engine sends together. The run table (planned `RunTable`) holds every run of one engine check, with every measure of each run. Defined in `engine_plan.md` ("Glossary"), §1.5.
- **`sigma(3)`**: the default confidence. Range knobs can take any value in their range, and statistical knobs together must be no less likely than a 3σ event. The worst such knob point is the 3σ point. Defined in `engine.md` §3.6, `walkthrough.md` §5.4.
- **spec side**: one direction of a spec. `bias` has two spec sides, `bias.max` (≤ 6.5 V) and `bias.min` (≥ 4.5 V), and the CE amp has 5. Defined in `engine_plan.md` ("Glossary").
- **verdict**: the answer of the engine for one spec side at one confidence. The words are FAIL, PASS (all corners), PASS (estimated), PASS (implied by worst case) and UNDECIDED (reason). A number outside a verdict has a status, `simulated` or `stale`. Defined in `engine_plan.md` §3.2, §3.6 (decision D-E). Do not call a PASS "verified".
- **worker**: a separate process that loads libngspice and runs the requests of the engine, so that a crash stops only the worker. Decision D-B chose a worker, and that choice is open again (`roadmap.md` §3). Defined in `engine_plan.md` §4.1, `roadmap.md` §3. Do not call it: "cold worker". Not the same as the worker thread of the TUI (terminal user interface).
- **worst-point loop** (planned `Strategy::FlipWalk`): the search that replaces corner enumeration when a cone has more than about 12 knobs. It draws a line from slopes, simulates the predicted worst corner, then flips knobs one at a time. It comes after the MVP. Defined in `engine.md` §5.8, `walkthrough.md` §10. Do not call it: "the loop", "worst-case loop", "worst-case-distance loop", "sensitivity loop", "flip walk".
- **`worst_case`**: the confidence that lets every knob, statistical knobs included, take any value in its range. The engine simulates every corner of the cone, then runs the guards. Defined in `engine.md` §3.6, §5.3.

<a name="ee"></a>
## Electrical engineering basics

- **analysis** (`spicy_circuit::Analysis`): one kind of simulation: op, AC or tran. The operating point (op) is the DC voltage of every node at rest. AC (alternating current) analysis gives the response to a small sine wave at each frequency, around the operating point. Transient analysis (tran) runs in time. Defined in `cli_plan.md` (term table), `language.md` §8.4.
- **beta** (β): the current gain of a BJT (bipolar junction transistor): the collector current divided by the base current. The part field is `beta`, the model parameter is BF, and datasheets call it hFE. Defined in `walkthrough.md` §1, §3, `engine_plan.md` §2.1. Do not call it: "gain" (the gain of an amplifier).
- **BJT** (bipolar junction transistor): a transistor with three pins: collector `c`, base `b` and emitter `e`. NPN (negative-positive-negative) is one of its two polarities, and `q1` in the CE amp is an NPN (`Npn` in the prelude). Defined in `walkthrough.md` §1, `language.md` §0.
- **CE amp** (common-emitter amplifier): the example design of the project, `circuits/ce_amp.spl`. It is a one-transistor audio amplifier with 8 knobs and three specs: `bias`, `gain` and `bass`. Defined in `walkthrough.md` §1.
- **f_low** (low cutoff frequency): the low frequency where the gain falls to 3 dB (decibels) under its peak, a factor of 0.708. The measure is `h.f_low(-3dB)`, about 20 Hz on the CE amp. Defined in `walkthrough.md` §1 and Appendix, `engine_plan.md` §4.6. Do not call it: "f_L".
- **gain**: the output amplitude divided by the input amplitude. The `gain` spec of the CE amp measures it at 1 kHz with `h.at(1kHz).mag()`, and its nominal is about 4.6. Defined in `walkthrough.md` §1.
- **linear**: a linear circuit has only elements such as resistors, capacitors and sources. Under the conditions of `engine.md` §4.2, its extremes lie at corners. A transistor makes a circuit nonlinear. Defined in `walkthrough.md` §7. Not the same as a straight-line estimate (an affine form).
- **model card**: a SPICE (Simulation Program with Integrated Circuit Emphasis) `.model` line that gives the parameters of a device model, for example `.model QM_q1 NPN(IS=1e-14 BF={k7} XTB=1.5 …)`. XTB sets how β changes with temperature. In the code: `spicy_circuit::BjtModel`. Defined in `engine_plan.md` §1.4, §2.1 (decision D-A).
- **Monte Carlo**: simulating many random knob points drawn from the spreads, to estimate how often a design fails. It answers "how often", never "how bad", so it never proves a PASS. It is not in the MVP. Defined in `engine.md` P5, §4.4, `walkthrough.md` §6.
- **nominal**: the value as designed, with no variation. The nominal of a knob is the value written before `±`, or the midpoint of a range: `beta: 100..=300` gives 200. Defined in `model.md` E16.
- **sensitivity**: a slope: how much a measure moves when one knob moves a little. On ngspice, the engine nudges each knob by 1% of its half-range, with one run for each knob. Defined in `walkthrough.md` §10.2, `engine.md` §6.2.
- **sigma** (σ): the standard deviation of a spread. The engine models the spread of a part as a normal distribution with σ = tolerance / 3, cut at the tolerance. Defined in `engine.md` §2.4, `walkthrough.md` §5.4.
- **TNOM** (nominal temperature): the temperature that the parameters of a model card apply to. ngspice uses 27 °C when the card gives none, and the default `Npn` model writes 25 °C (decision D-A). Defined in `engine_plan.md` §2.1, §5.2.
- **tolerance**: how far a real part may be from its nominal, for example `47k ± 1%`. Each part field with a tolerance becomes a statistical knob. Defined in `language.md` §5.2–5.4.
- **worst-case analysis**: checking a circuit with every varying value at its worst combination. The engine does it with the confidence `worst_case`. Defined in `walkthrough.md` §3, `engine.md` §3.6.

<a name="simulators"></a>
## Simulators, netlists and commands

- **KLU**: a sparse LU (lower-upper) factorization library for circuit matrices, by Davis and Palamadai Natarajan (2010). Our simulator uses its own port, `spicy_simulate::solver::klu`. Defined in `bibliography.md`, `vision.md` §3.
- **MNA** (modified nodal analysis): the method that SPICE uses to write a circuit as one matrix equation. It has one row for each node voltage, and one branch row for each voltage source or inductor current. Used in `circuit.md` §2, §4.3. Do not call a branch row an "MNA row" or a "branch current" (the unknown in that row).
- **netlist**: a SPICE text file that lists the parts, the nets between them, and analysis commands. The netlist reader (`spicy_netlist::reader::parse`) reads it into a `Deck`. Defined in `cli_plan.md` (term table), `netlist_reader.md`. Do not call it: "deck", except in the name "engine deck".
- **netlist writer** (`spicy_netlist::writer::write`): the code that turns a `Lowered` circuit back into SPICE text that ngspice runs. The export (milestone M1f, `spicy export`) is lowering followed by the writer. Defined in `netlist_writer.md` §1. Do not call it: "exporter", "numeric SPICE writer", "M1f".
- **ngspice**: the open-source SPICE simulator that the engine uses first (decision D-B). libngspice is ngspice built as a shared library that another program loads. Defined in `engine.md` §6.3, `engine_plan.md` §4.
- **our simulator** (`spicy_simulate`): the SPICE-style simulator of this project. It reads only `spicy_circuit`, and it becomes the second backend of the engine in milestone M4. `spicy sim` runs it by default. Defined in `ARCHITECTURE.md#code-map`, `engine.md` §6.5, `cli_plan.md` CLI-3.
- **SPICE** (Simulation Program with Integrated Circuit Emphasis): the classic circuit simulator. Its netlist language has dialects, which ngspice, Xyce and our netlist reader read. Used in `netlist_reader.md`.
- **`spicy check`**: the command that runs the front end only: lex, parse, resolve, flatten, and the checks for simulation. It never simulates. Defined in `cli_plan.md` CLI-1 (decided 2026-10-02). Not the same as an engine check: the engine docs still write `spicy check` for the engine.
- **`spicy test`**: the planned command that runs an engine check and prints the verdicts. Its name is on hold until the engine design goes further. Defined in `cli_plan.md` CLI-1.
- **`spicy_circuit::Circuit`**: the wiring that the simulator reads: nodes and devices, with no numbers. `Params` holds the numbers, and `Lowered` holds both, with the names, the analyses and the solver options. Defined in `pipeline.md` §3, `circuit.md`. Not the same as the `circuit` item of the language.
- **stamp location**: the matrix entries where one device adds its values. To stamp a device is to add its values at its stamp locations before each solve. Defined in `pipeline.md` §1–3. Do not call it: "stamp index", "stamp position", "matrix position", "matrix slot".

<a name="how-we-work"></a>
## How we work

- **decision ID** (decision identifier): the label of one decision, with the prefix of its doc, for example `CLI-4` (`cli_plan.md`), `E16` (`model.md`), `T5` (`engine_types.md`) or `D-A` (`engine_plan.md`). Always write it with its short name: "`CLI-4` (exit codes)". Defined in `docs/writing_docs.md` ("Make links and numbers that do not break").
- **milestone**: one unit of work in the roadmap, with an ID from M0 to M8. A letter after the number names a part of it, for example M1d (elaboration) or M3a (the engine design note). Each part ends at a review point (🔍). Always write the meaning next to the ID. Defined in `roadmap.md` §6.
- **MVP** (minimum viable product): "spicy reads `circuits/ce_amp.spl`, checks its three specs on ngspice, and prints a verdict for each spec." Each verdict must match the answer key. Defined in `roadmap.md` (the first lines).
- **other session**: another Claude Code session that works in the same repository at the same time. For example, one session works on the language and one on the engine. Used in `engine_plan.md` §5, `cli_plan.md`. Do not call it: "peer".
- **plan step**: one numbered step of one plan doc. Several plans have a step 2, so always name the plan: "contracts plan, step 2". Plans with steps include `syntax_v5_plan.md`, `contracts_plan.md`, `cli_plan.md` and `pipeline.md` §9. Defined in `AGENTS.md` (rule 2).
- **reference**: another project whose source or specification we read to ground a decision, for example rustc, rust-analyzer, Zig, Spade, atopile, ngspice, Xyce or Modelica. Defined in `.claude/commands/stage-review.md`.
- **snapshot test**: a test that compares an output with a stored file in a `snapshots/` folder. A case file is a small input under `test_data/<stage>/{ok,err}` that a snapshot test reads. Defined in `roadmap.md` §5, `.claude/commands/stage-review.md`.
- **stage review** (`/stage-review`): the cleanup review of one stage, with subagents for references, flows and types, plus fuzzing and a benchmark before and after. Defined in `.claude/commands/stage-review.md`. Do not call it: "the review" (a review can also be a research report).
- **state words**: the words that a status update uses for the state of the work: done, running, next, not committed. Defined in `AGENTS.md` (rule 9). Do not use another word for one of these states, for example "finished" for done.
